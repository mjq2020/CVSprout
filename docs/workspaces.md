# 个人工作空间与项目分享

账号分为系统管理员（`admin`）和普通用户（`user`）。普通用户可以创建项目；新项目默认私有，系统管理员可以查看和管理所有项目。

首页的“我的项目”显示自己拥有的项目，“分享给我的”显示其他人添加自己为成员的项目。系统管理员另有“全部项目”。每个范围都可以切换查看已归档项目，归档不改变访问权限。

## 分享项目

所有者进入项目，点击“项目成员与分享”，输入对方完整登录账号，选择权限后添加。被添加的账号须已启用；无需公开全站用户目录。分享只适用于当前项目。

| 项目身份 | 可执行操作 |
|---|---|
| 所有者 | 上传、标注、审核、标签维护、任务块、版本、训练、转换、下载；管理成员、归档、删除项目 |
| 协作者 `editor` | 上传、标注、审核、标签维护、任务块、版本、训练、转换、下载；不能分享、归档或删除整个项目 |
| 只读成员 `viewer` | 查看图片、标注、任务和训练结果；默认不能下载或导出，可由所有者单独授权 |

系统管理员始终拥有管理权限。账号管理、系统模型配置、共享权重导入和边缘设备管理仍由系统管理员负责。

任务块归属、编辑锁、审核状态、版本冲突等原有规则继续生效。项目协作权限不会覆盖他人已领取任务块的编辑保护；标注和审核无需由不同人员完成。

移除成员后，其后续请求（包括旧链接和直接使用资源 ID 的请求）无法访问该项目。降为只读或移除成员会释放其图片编辑占用和任务块，取消其未完成的 AI 标注任务，保留已有标注和审计记录。已经提交的训练/转换属于项目，继续运行；被移除的成员不能再查看、操作或下载它们。已下载到本地的文件无法收回。

## 从旧版升级

数据库迁移 16 在首次启动时执行，之后重复启动不会重置所有权或成员。

1. 默认保留最早创建、仍启用的管理员为系统管理员；其他旧管理员、标注员、审核员转为普通用户。
2. 如需指定保留的账号，在首次升级前设置 `MDP_SYSTEM_ADMIN_USERNAME=完整登录账号`。该账号必须是已有且启用的管理员；配置无效时迁移回滚并停止启动。
3. 根据项目创建审计记录中的账号确定旧项目所有者。使用令牌、开发身份创建或无法确认归属的项目暂时没有所有者，只有系统管理员可访问。
4. 系统管理员在“全部项目”打开项目，在“项目成员与分享 → 分配项目所有者”中输入普通用户账号。也可转交已有项目；原所有者不再自动拥有访问权，已有分享成员保留原权限。
5. 旧会话会失效，需要重新登录；密码和已有数据保留。旧共享关系不会自动继承，所有者需要明确添加协作成员。

迁移在一个数据库事务内执行并检查外键。升级前应按既有部署流程备份数据目录。`disabled` 开发模式和管理令牌仍代表系统管理员身份，个人空间隔离应使用 `accounts` 模式验证。

## API

| 接口 | 用途 |
|---|---|
| `GET /api/projects?scope=mine/shared/all&archived=false` | 自有、被分享或全部项目；`all` 仅系统管理员可用 |
| `GET /api/projects/{id}/members` | 所有者或系统管理员查看项目成员 |
| `PUT /api/projects/{id}/members` | 添加或更新成员：`{"username":"bob","role":"viewer","can_export":false}` |
| `DELETE /api/projects/{id}/members/{user_id}` | 撤销分享 |
| `PUT /api/projects/{id}/owner` | 系统管理员分配所有者：`{"username":"alice"}` |

项目列表和详情返回 `project_role`、`is_owner` 与 `permissions.edit/manage/export`。未指定 `scope` 时返回当前账号可访问的项目。后端对项目、图片、标注、任务、数据版本、训练及转换产物统一校验项目成员关系；没有访问权和不存在的资源均返回 404，只读操作越权返回 403。

核心实现为 `app/project_access.py`、`app/project_migration.py`；隔离与迁移回归测试为 `tests/test_project_access.py`、`tests/test_project_migration.py`。
