# CVSprout Capture

将 reCamera Pro 原始彩色画面直接送入 CVSprout 项目，无需手工拷贝。仅使用 Kit 共享相机帧，不占用 NPU，也不会把画面中的检测框烧录到采集图中。

## 使用

1. 在 CVSprout 的设备页面创建一个绑定项目的设备，复制只显示一次的设备令牌。
2. 在设备应用中心上传 `cvsprout-capture` 的 `.tar.gz` 包并安装。
3. 在应用参数中填写设备可访问的 `server_url`（例如 `http://192.168.1.10:8008`）和 `device_token`，保存后启动。不要填写 `127.0.0.1`，它在设备上指向设备自身。
4. 在 CVSprout 设备页设置采集间隔、开始或暂停采集。图片自动进入绑定项目，可继续 AI 标注、分块领取、人工审核和训练。

初始服务地址和令牌为空，需配置后才能启动。凭据仅存在设备应用配置中，不写入采集队列、日志或应用压缩包。公网通信应配置有效 HTTPS 证书；应用拒绝自动跳转，不会把设备令牌带到其他站点。

## 参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `server_url` | 空 | CVSprout 服务根地址，可含反向代理路径前缀 |
| `device_token` | 空 | 对应设备的专用令牌，不能替代管理员账户 |
| `jpeg_quality` | 90 | 原始尺寸 JPEG 质量，40–95 |
| `spool_size_mb` | 128 | 离线队列容量，16–512 MiB |
| `spool_max_images` | 1000 | 队列最多图片数，10–10000 |
| `max_session_images` | 0 | 本次应用启动最多采集数量，0 表示不限；重启重新计数 |

以上设备参数修改后需重启。服务端的启停和间隔每 30 秒同步一次，连接心跳每 15 秒上报，关键状态变化会提前上报。断网时可继续排队最多 5 分钟，此后暂停新增图片，恢复连接后重新同步配置。令牌撤销后收到认证失败会立即暂停。暂停采集不删除已有队列。

## 确认连接与排查不上传

1.0.2 会先检查令牌格式。必须复制 CVSprout 创建或重置设备时显示的完整 `cvsprout_device_...` 令牌，不能填写设备 ID、设备登录密码或管理员令牌。令牌缺失或格式错误会以 `device_token_invalid` 明确阻止启动。不要把真实令牌粘贴到日志或问题报告中。

启动后查看应用日志：`server_configuration_received` 表示服务地址和设备身份验证成功，`server_confirmed` 表示服务器已确认心跳，`first_frame_received` 表示 Kit 已交付原始画面，`first_image_queued` 表示首张 JPEG 已写入可靠队列，`first_image_confirmed` 才表示服务器已经收到图片。SDK 自身输出的 `dets=0 events=0 clients=0` 只是结果通道统计，其中 `clients=0` 不是图片上传连接失败。

| 日志错误 | 处理方式 |
| --- | --- |
| `http_401` / `http_403` | 在 CVSprout 设备页重置令牌，把完整新令牌更新到设备应用参数后重启；原令牌会失效 |
| `server_connection_refused` | 确认 CVSprout 已启动、地址与端口正确，并监听局域网可访问的地址 |
| `server_timeout` / `server_dns_failed` | 检查设备网络、域名和防火墙；`127.0.0.1` 指向设备自身 |
| `server_tls_verification_failed` | 检查 HTTPS 证书与设备时间，不要关闭证书校验 |
| `server_redirect_refused` | 使用服务最终地址，避免 HTTP 到 HTTPS 或登录页跳转 |
| `jpeg_encode_failed` / `image_exceeds_server_limit` | 检查相机帧和图片大小，可降低 JPEG 质量后重启 |
| `spool_full_capture_paused` | 队列已满，恢复上传后自动继续；未确认图片不会被删除 |

即使相机暂未交付画面，网络线程仍会连接并发心跳。新版本 CVSprout 设备页可以区分等待配置、等待画面、采集中、服务端暂停、达到本次采集上限、队列已满及采集错误，并显示画面数、已采集数、待上传数和上传确认数。超过 15 秒未收到新画面时状态会变为等待画面，不能把“应用运行中”当成采集成功。新版应用连接旧版 CVSprout 时自动使用原有心跳字段，避免额外字段被拒绝。

队列位于 Kit 公共 `appdata_root()/cvsprout-capture/capture-spool/`，应用升级保留数据。每张图以单个文件保存 JPEG、固定 `capture_id`、所属设备身份和 SHA-256 校验值。写入临时文件后同步文件，再原子改名并同步目录；重启后读取已提交记录并清理未提交临时文件。上传前检查长度和校验值，损坏记录会保留并报 `capture_spool_corrupt`，不会上传损坏数据或自动删除图片。

仅当服务返回同一 ID、有效 `asset_id` 和 `received=true` 才删除本地记录。容量用完或磁盘已满时暂停新增，绝不淘汰未确认图片；恢复空间后继续上传。若文件已发布但目录同步失败，则保留记录并以 `spool_storage_error` 停止本次运行，修复存储后重启恢复。改换服务或绑定身份后，旧队列不会发给新的项目。需要处理旧队列时恢复原设备身份。不要手动修改队列文件。

`spool_size_mb` 限制待上传 JPEG 的字节总量；每条记录另有最多 2 KiB 元数据和文件系统分配开销，单次写入最多 10 MiB，队列最多 10000 张。应用声明 **1152 MiB** 存储预算，为最大 512 MiB JPEG 队列、文件系统元数据及临时写入留有余量。已确认记录删除后立即释放文件空间，没有数据库回滚日志或历史高水位文件。采集和上传线程通过锁串行修改队列；AppMgr 的单实例约束避免多个进程同时写入。

## 从 1.0.0 升级

1.0.1 不再依赖 `sqlite3` / `_sqlite3`，因此设备的精简 Python 缺少这些模块也可加载采集应用。若 1.0.0 一启动就报告 `No module named 'sqlite3'`，它尚未创建离线数据库，直接在应用中心上传并升级至 1.0.1，保留服务地址和设备令牌配置后启动即可，无需修改固件或安装系统 Python 模块。

如果旧版曾正常运行，应用会检查 `captures.sqlite3` 及其 `-journal`、`-wal`、`-shm` 文件；发现任何旧文件均停止启动并提示 `legacy_spool_migration_required`，原文件保留不动，避免升级后遗漏尚未上传的图片。请先在原有兼容运行环境中用 1.0.0 暂停新增采集，保持原服务和设备身份，等待队列全部上传并确认服务器已收到，再停止应用、备份并归档这组旧数据库文件，使其不再位于原文件名下，然后通过应用中心启动 1.0.1。即使旧队列已清空，数据库文件仍存在，也需要归档。若旧环境无法运行或不能确定是否上传完成，保留整组文件并联系维护者导出恢复，不要直接删除、改写或只复制主数据库。

## 验证与限制

Python 核心标准库负责 HTTP 和文件队列，不使用 SQLite；`kit`、`numpy`、`cv2` 由设备的 `recamera-ai-cp311-v1` 运行环境提供，不随包复制。目标为 RV1126B、aarch64、Python 3.11。已验证缺少 SQLite 的独立 Python 3.11 进程中的 Kit 加载、离线队列重启、重试与回执，以及磁盘满、原子提交顺序、并发容量和损坏数据保护；真实固件帧服务、网络上传和长时间运行仍需设备验收。

构建和测试命令见 SDK 仓库 `tests/cvsprout/README.md`。本应用源码使用 Apache-2.0，见 `LICENSE`。
