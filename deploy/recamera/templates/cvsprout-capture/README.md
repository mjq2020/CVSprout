# CVSprout Capture

将 reCamera Pro 原始彩色画面直接送入 CVSprout 项目，无需手工拷贝。仅使用 Kit 共享相机帧，不占用 NPU，也不会把画面中的检测框烧录到采集图中。

## 使用

1. 在 CVSprout 的设备页面创建一个绑定项目的设备，复制只显示一次的设备令牌。
2. 在设备应用中心上传 `cvsprout-capture` 的 `.tar.gz` 包并安装。
3. 在应用参数中填写设备可访问的 `server_url`（例如 `http://192.168.1.10:8008`）和 `device_token`，保存后启动。不要填写 `127.0.0.1`，它在设备上指向设备自身。
4. 在 CVSprout 设备页设置采集间隔、开始或暂停采集。图片自动进入绑定项目，可继续 AI 标注、分块领取、人工审核和训练。

初始服务地址和令牌为空，需配置后才能启动。凭据仅存在设备应用配置中，不写入采集队列、日志或应用压缩包。公网通信应配置有效 HTTPS 证书；应用拒绝自动跳转，不会把设备令牌带到其他站点。

## 参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `server_url` | 空 | CVSprout 服务根地址，可含反向代理路径前缀 |
| `device_token` | 空 | 对应设备的专用令牌，不能替代管理员账户 |
| `jpeg_quality` | 90 | 原始尺寸 JPEG 质量，40–95 |
| `spool_size_mb` | 128 | 离线队列容量，16–512 MiB |
| `spool_max_images` | 1000 | 队列最多图片数，10–10000 |
| `max_session_images` | 0 | 本次应用启动最多采集数量，0 表示不限；重启重新计数 |

以上设备参数修改后需重启。服务端的启停和间隔每 30 秒同步一次。断网时可继续排队最多 5 分钟，此后暂停新增图片，恢复连接后重新同步配置。令牌撤销后收到认证失败会立即暂停。暂停采集不删除已有队列。

队列位于 Kit 公共 `appdata_root()/cvsprout-capture/captures.sqlite3`，应用升级保留数据。每张图使用固定 `capture_id`，重试保持不变；仅当服务返回同一 ID、有效 `asset_id` 和 `received=true` 才删除本地记录。容量用完时暂停新增，绝不淘汰未确认图片。改换服务或绑定身份后，旧队列不会发给新的项目。需要处理旧队列时恢复原设备身份；不要直接修改数据库。

`spool_size_mb` 限制的是待上传 JPEG 的逻辑字节数，不是数据库文件大小。SQLite 会复用空闲页，删除已确认图片后数据库文件通常保留历史峰值。应用另用 `max_page_count` 将数据库主文件硬性限制为 560 MiB，使用 DELETE 回滚日志而非持续增长的 WAL。manifest 为主文件、最坏情况下接近同体积的临时回滚日志及其他开销预留 **1152 MiB**。触及物理页上限或磁盘已满时暂停新增图片，保留已有队列，恢复空间后继续；不会为缩小文件自动执行 VACUUM 或删除未确认记录。

## 验证与限制

Python 标准库负责 HTTP 和 SQLite；`kit`、`numpy`、`cv2` 由设备的 `recamera-ai-cp311-v1` 运行环境提供，不随包复制。目标为 RV1126B、aarch64、Python 3.11。已编写离线队列、重试、回执、颜色和 Kit 加载测试；真实固件帧服务、网络上传和长时间运行仍需设备验收。

构建和测试命令见 SDK 仓库 `tests/cvsprout/README.md`。本应用源码使用 Apache-2.0，见 `LICENSE`。
